# Prune + gap analysis (in-session, after the conductor chain)

You are an AI agent. Your job is to analyze the project's context (the
`.context/` files already generated by the previous bootstrap steps) and
identify:

- Which toolkit resources installed by `ai-toolkit init` are NOT relevant
  to this project (candidates for removal).
- Which resources are MISSING but would be useful (gaps to fill).

This step runs **inside the conductor's chat session** (not in an isolated
sub-agent). The conductor invokes it as the last sub-prompt (step 8) and
passes the discovery JSON, the path to `.ai-toolkit.json`, and the target
repo path.

## Inputs

- Repo target: absolute path to the target repo.
- Discovery JSON (from step 2).
- `.context/stack.md`
- `.context/architecture.md`
- `.context/code-style.md`
- `.context/conventions.md` (if generated)
- `.context/examples/` (if generated)
- `AGENTS.md` (from step 7)
- State file: `<target>/.ai-toolkit.json` (lists what was installed)

## Output

**Print to stdout only. Do NOT create any file.**

Two tables:

### Recommended removals

| Resource | Type | Reason | Safe-to-remove |
|----------|------|--------|----------------|
| react-native-expo | skill | Project is a Python backend, no mobile | yes |
| ... | ... | ... | ... |

### Suggested additions

| Resource | Type | Reason | How to install |
|----------|------|--------|----------------|
| redis-best-practices | skill | Stack mentions Redis usage | ai-toolkit init --skills=redis |
| ... | ... | ... | ... |

## Scope

**INCLUDE in the analysis (candidates for removal/addition):**

- Agents (`.opencode/agents/` or `.claude/agents/`)
- Skills (`.opencode/skills/` or `.claude/skills/`)
- Commands (`.opencode/commands/`)
- Prompts (if installed at `.opencode/prompts/` or similar)
- MCPs (`.opencode/mcp.json` or `.mcp.json`)

**EXCLUDE from the analysis (do NOT touch):**

- Source code (any `src/`, `lib/`, `app/`, etc.)
- Tests (any `tests/`, `test/`, `__tests__/`, etc.)
- Dependencies (manifests: `package.json`, `pyproject.toml`, `go.mod`, etc.)
- Lockfiles (`package-lock.json`, `yarn.lock`, `poetry.lock`, etc.)
- User-created files outside what `ai-toolkit init` installed
  (verify against `.ai-toolkit.json` state)

## Logic

### Recommended removals

For each resource listed in `.ai-toolkit.json`, check whether it makes
sense in this project's context (read `.context/stack.md` and
`.context/architecture.md`):

- If the resource targets a stack/language/framework NOT used by this
  project → recommend removal.
- If the resource is a duplicate of another installed resource →
  recommend removal.
- If the resource's description matches the project's domain loosely but
  is not core to the workflow → recommend with a `safe-to-remove: yes`
  flag.

### Suggested additions

Based on the `.context/` files, identify gaps:

- If `stack.md` mentions a tool/framework that has no matching
  skill/agent → suggest adding it (with install command:
  `ai-toolkit init --skills=<name>`).
- If `architecture.md` describes a domain (e.g. payments, auth, async
  jobs) that has no specific skill/agent → suggest.
- If the project uses patterns that aren't covered by existing skills
  (e.g. testing with Playwright, deployment with K8s) → suggest.

## Apply mode (optional, default: dry-run)

By default, this step is a **DRY-RUN**: print suggestions to stdout only,
do NOT remove anything. The developer reviews the suggestions and
decides.

If the developer invokes this step with the word "apply" or "execute"
(e.g. "yes apply" or "execute the prune"), then for each row in
"Recommended removals" with `safe-to-remove: yes`, the agent removes the
corresponding file. Suggested additions are NEVER auto-installed in this
step (they are out of scope — the developer runs `ai-toolkit init
--skills=<name>` separately).

### Safety guards (apply mode only)

When you actually remove files, **all of the following must hold**. If
any guard fails, refuse the removal and keep going to the next row
(printing the refusal) — do NOT crash the batch.

1. **Canonicalize the path** with `realpath` (POSIX) or `path.resolve()`
   (Node) before passing to `rm`. Never pass a path containing `..` or a
   symlink you have not resolved.
2. **Verify the canonical path is inside the target project root.** A
   canonical path that resolves above `<target>/` (or anywhere outside)
   must be refused.
3. **Verify the path is in `.ai-toolkit.json` state.** If the row is not
   listed under `state.tools[tool].<resource-type>` (or the equivalent
   array of installed resources), it was NOT installed by `ai-toolkit
   init` and must be refused (it may be a user-created file).
4. **Print every removal BEFORE executing it**, with the canonical path
   and the reason copied from the table. No silent deletes.
5. **Execute all removals in a single batch command.** Do NOT loop with
   `sleep` between removals — pick the entire batch atomically, print the
   plan, then run a single `rm` invocation (or a list of explicit
   `rm` lines inside one script). The developer can interrupt the script
   with Ctrl+C if they spot a mistake before it runs.

Example safe removal (POSIX):

```bash
canonical=$(realpath "$file" 2>/dev/null || echo "$file")
if [[ "$canonical" != "$target"/* ]]; then
  echo "  Refusing to remove: $canonical is outside target"
  continue
fi
echo "  Removing: $canonical (reason: <copy from table>)"
rm "$canonical"
```

Example safe removal (Node):

```js
const canonical = path.resolve(target, file);
if (!canonical.startsWith(path.resolve(target) + path.sep)) {
  console.log(`  Refusing to remove: ${canonical} is outside target`);
  continue;
}
console.log(`  Removing: ${canonical} (reason: <copy from table>)`);
await fs.unlink(canonical);
```

At the end of the batch, print a summary:

```
Removed: N files
Skipped (refused by guard): M files
Suggested additions: K (not installed — developer must run ai-toolkit init)
```

## Absolute rules

1. **Do not invent.** Base suggestions on what you can verify in the
   `.context/` files or the source code. If you cannot verify a claim,
   omit the row.
2. **When in doubt, leave it.** Better to leave an extra skill than to
   delete a useful one. Mark the row `safe-to-remove: no` if uncertain.
3. **No file output.** Print to stdout only.
4. **No emoji in output.** Tables only.
5. **Apply mode refuses, never crashes.** If a guard refuses a removal,
   print the reason, continue with the next row, and report the count
   of refused rows in the final summary.

## Edge cases

- **`.ai-toolkit.json` missing or empty** → skip the analysis entirely
  and report: `Cannot analyze: no install state found at
  <path>/.ai-toolkit.json`. Do NOT guess what was installed.
- **`.ai-toolkit.json` exists but is malformed (invalid JSON, wrong
  shape)** → skip the analysis and report: `Cannot analyze: install
  state at <path>/.ai-toolkit.json is not valid JSON or has unexpected
  shape. Re-run \`ai-toolkit init\` to regenerate it.`
- **A `.context/` file referenced by Inputs is missing** → proceed with
  the files you have; note the missing file in a `Notes` section before
  the tables. Do NOT abort the analysis.
- **In apply mode, a row marked `safe-to-remove: yes` cannot be verified
  against the state** (file not listed, or path resolves outside
  target) → refuse that row, print the reason, continue the batch. The
  summary must include the count of refused rows.

## Tone and style

- **Concise, factual.** No verbosity.
- **Tables only for the two required outputs.** Free text only for the
  summary, the notes section, and the per-row refusal messages in apply
  mode.
- **No emojis.**
- **No exclamation marks, no welcome text.**
- **Output language**: same as the developer's chat language. If unclear,
  default to English; use Spanish if the developer prefers Spanish.
