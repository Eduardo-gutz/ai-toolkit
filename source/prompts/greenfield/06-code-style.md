# Code style: generate `.context/code-style.md`

You are an AI agent. Your job is to generate **a single file** in the
target repo: `.context/code-style.md`.

## Inputs

- Target repo: path of the repo to initialize.
- Standards JSON: the complete JSON produced by `03-standards.md`. You
  especially need `standards.code_style.*` and `standards.testing.*`.
- Prescribed patterns: the `## Prescribed patterns` section of
  `./defaults/<stack>.md` (and `./defaults/_baseline.md` for the generic
  ones).

## Output

**A single file**: `<repo>/.context/code-style.md`.

If the file already exists, **ask the user** before overwriting (show
them a proposed diff section by section).

## Absolute rules

- **Every asserted value carries its provenance marker.** The legend is
  written once, at the top of the file:

  ```markdown
  > Provenance legend — `[confirmed]`: the developer stated it in the
  > interview. `[default: <file>]`: it comes verbatim from the stack
  > defaults catalog. `[pending]`: undecided — the value is `null` and it
  > is listed in `open_questions`.
  ```

  Then every line that asserts a value renders its marker, for example
  `camelCase — [confirmed]`, `kebab-case — [default: defaults/_baseline.md]`
  or `Comment policy — [pending]`.
- A `[default: …]` marker MUST name the catalog file the value came from.
- A `[pending]` line MUST show the value as `not decided` — never a
  placeholder guess.
- **No "real snippets" section.** A greenfield project has no code, so
  there is nothing to extract. Where `/bootstrap` would embed a snippet
  from the repo, this file embeds a **prescribed pattern** — a template
  taken from the catalog's `## Prescribed patterns` section — and states
  in one line that it is a **template, not an extraction**.
- Every prescribed pattern MUST be marked `[default: defaults/<stack>.md]`
  (or `[default: defaults/_baseline.md]`), and MUST be labelled as a
  template.
- Do not add emojis.
- The file must be **100% derivable from the standards JSON and the
  catalog files**.

## How to derive each section

### Linters and formatting

Take `stack.linter` and `stack.formatter` from the standards JSON. The
config file names come from the same catalog rows. When the value is
`[pending]`, write `not decided — see open_questions` and omit the config
name.

### Import order

Take `standards.code_style.imports_order` verbatim, with its marker, and
expand it into the concrete group order.

### Naming conventions

One row per element, from `standards.code_style.naming_files`,
`naming_classes`, `naming_functions`, `naming_variables` and
`naming_constants`. Each row carries its own marker.

### Error handling

Take `standards.code_style.error_handling_pattern` verbatim, with its
marker, and add the concrete error shape from the catalog's prescribed
patterns.

### Async model

Take `standards.code_style.async_pattern` verbatim, with its marker.

### Module exports

Take `standards.code_style.export_style` verbatim, with its marker.

### Comments

Take `standards.code_style.comments` verbatim, with its marker. When it
is `[pending]`, state that the policy is undecided.

### Tests

One bullet per `standards.testing.*` leaf, each with its own marker.

### Prescribed patterns

Copy the templates from the `## Prescribed patterns` section of
`./defaults/<stack>.md` (falling back to `./defaults/_baseline.md` for the
generic ones). Reproduce them **verbatim** — they are code, not prose.
Each pattern gets its own heading, its one-line "what it is", the fenced
template, and the source line naming the catalog file.
