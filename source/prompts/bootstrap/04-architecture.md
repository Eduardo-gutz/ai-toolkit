# Architecture: generate `.context/architecture.md`

You are an AI agent. Your job is to generate **a single file** in the
target repo: `.context/architecture.md`.

## Inputs

- Target repo: path of the repo to analyze.
- Discovery JSON: the complete JSON produced by `02-discovery.md`. You
  especially need `structure`, `samples`, `cross_cutting`.

## Output

**A single file**: `<repo>/.context/architecture.md`.

If the file already exists, **ask the user** before overwriting (show
them a proposed diff section by section).

## Absolute rules

- Do not invent: if you did not find data in the code or in the
  discovery JSON, declare it as "pending" or "not found".
- Do not copy architectures from other projects. Analyze ONLY this repo.
- Do not add emojis.
- Cite real paths (verify they exist by reading the filesystem).
- If the structure does not fit "layers" or "features", describe it as
  it is — do not force a label.

## How to derive each section

### Structure type

Use the `structure.type` field of the discovery JSON. If it is
`"unknown"`, look at the `top_dirs` manually and pick the best label.

### Folder tree

Use `structure.top_dirs` and `structure.src_dirs` from the discovery
JSON. List each folder with a 1-line comment about its contents. If
you need to verify what is inside, read the directory with `ls` or
equivalent.

### Layers and responsibilities

Infer from the discovery JSON samples:

- If `samples.router` exists, see what it imports → that tells you
  which layers exist below.
- If `samples.service` exists, see which layers it consumes.
- Repeat for `samples.model` and `samples.test`.

If the repo has a clear layered structure, fill in the table. If it is
feature-based, fill it in with features instead of layers.

### Domains / features

List the main subfolders inside `src/` or `app/`. If the names are not
obvious, read the first `.controller`, `handler`, or `routes` file you
find to understand the domain.

### Naming conventions

Take 3-5 real examples of each file type in the repo and detect the
pattern. If there is no consistency, mark it as "mixed".

### Work unit flow

Follow the path from the entry point to the end, reading the real
files. Cite each step with a concrete path. If the flow varies by
feature, describe the most typical case and mention the variants.

### Storage / persistence

If the repo has migrations, schema files, or a configured ORM, fill in
this section. If not, omit it.

## If the discovery JSON has empty or "unknown" fields

Do not invent. If `structure.type` is `"unknown"`, describe it as
"unidentified structure — see folder tree above". If `samples.service`
is `null`, omit mentions of service layer and rephrase.

## Final output

Return to the conductor:

- The complete contents of the `.context/architecture.md` file you
  just created.
- A short note (1-2 lines) confirming the file was created.
