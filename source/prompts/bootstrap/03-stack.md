# Stack: generate `.context/stack.md`

You are an AI agent. Your job is to generate **a single file** in the
target repo: `.context/stack.md`.

## Inputs

- Target repo: path of the repo to analyze.
- Discovery JSON: the complete JSON produced by `02-discovery.md`. You
  especially need `repo`, `manifests`, `ci_cd` and `env_and_secrets`.

## Output

**A single file**: `<repo>/.context/stack.md`.

If the file already exists, **ask the user** before overwriting (show
them a proposed diff section by section).

## Absolute rules

- Do not invent: if you did not find a technology in the code or in the
  discovery JSON, declare it as "not found" or "pending". Do not fill
  gaps with assumptions about a "typical stack".
- Do not copy conventions from other projects. Analyze ONLY this repo.
- Do not add emojis.
- Cite real paths (verify they exist).
- **Exact** versions (verify with `grep` against the manifests — do not
  copy "from memory").
- **The file must be 100% derivable from the discovery JSON.** If you
  need info that is not in discovery, re-read the repo with `grep` or
  direct reading — do not invent.

## Expected output structure

The `.context/stack.md` file must have this structure (in this order).
If a section does not apply (e.g. the repo has no auth), omit it or
mark it as "not found".

### Header


## How to derive each section

### Tech table

List **all** dependencies (runtime + dev) from the key manifests.
Group by category:

- Language: the main language (Node, Python, Go, etc.).
- Framework: the dominant framework (Express, FastAPI, Gin, etc.).
- ORM / DB driver.
- Validation.
- Auth.
- HTTP client.
- Testing.
- Linter.
- Formatter.
- Logging.
- i18n.
- Build / bundler.

For each, note the **exact** version from the manifest. If you use a
lockfile (package-lock.json, poetry.lock, go.sum), cite the lockfile
version, not the manifest one (which may have caret/tilde).

### Usage rules

For each category that applies to the repo:

- Cite the file where it is initialized (with `path/to/file:line`).
- Cite the file where it is registered (with `path/to/file:line`).
- Cite the file where it is typically consumed (with `path/to/file:line`).

### Official documentation links

For each library listed in the tech table, look up its official
documentation URL. If you do not know it with certainty, mark it as
"verify" and do not invent.

## If the discovery JSON has empty or "unknown" fields

Do not invent. If `repo.framework` is `null`, mark it as "not found".
If `repo.test_framework` is `null`, write "not found" in the Tests
section. If you cannot infer anything about a category, omit it.

## Final output

Return to the conductor:

- The complete contents of the `.context/stack.md` file you just
  created.
- A short note (1-2 lines) confirming the file was created.
