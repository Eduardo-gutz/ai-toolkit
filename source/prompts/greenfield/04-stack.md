# Stack: generate `.context/stack.md`

You are an AI agent. Your job is to generate **a single file** in the
target repo: `.context/stack.md`.

## Inputs

- Target repo: path of the repo to initialize.
- Standards JSON: the complete JSON produced by `03-standards.md`. You
  especially need `stack.*` and `standards.testing.*`.
- Stack id: the `stack_id` the standards JSON was normalized against.

## Output

**A single file**: `<repo>/.context/stack.md`.

If the file already exists, **ask the user** before overwriting (show
them a proposed diff section by section).

## Absolute rules

- **Every asserted value carries its provenance marker.** The legend is
  written once, at the top of the file:

  ```markdown
  > Provenance legend — `[confirmed]`: the developer stated it in the
  > interview. `[default: <file>]`: it comes verbatim from the stack
  > defaults catalog. `[pending]`: undecided — the value is `null` and it
  > is listed in `open_questions`.
  ```

  Then every line that asserts a value renders its marker, for example
  `ESLint 9 — [confirmed]`, `Prettier 3 — [default: defaults/node-typescript.md]`
  or `Coverage gate — [pending]`.
- A `[default: …]` marker MUST name the catalog file the value came
  from: `defaults/_baseline.md` or `defaults/<stack>.md`.
- A `[pending]` line MUST show the value as `not decided` — never a
  placeholder guess.
- Do not copy conventions from other projects. Use only the standards
  JSON and the catalog files.
- Do not add emojis.
- Cite real paths (verify they exist).
- The file must be **100% derivable from the standards JSON**. If you
  need something that is not in it, it is `pending`.

## Expected output structure

The `.context/stack.md` file must have this structure (in this order).
If a section does not apply, omit it or mark it as `[pending]`.

## How to derive each section

### Tech table

One row per category that the standards JSON covers:

- **Language** — from `stack.language` + `stack.language_version`.
- **Framework** — from `stack.framework`.
- **Package manager** — from `stack.package_manager`.
- **Testing** — from `stack.test_framework` and `standards.testing.framework`.
- **Linter** — from `stack.linter`.
- **Formatter** — from `stack.formatter`.

Every row carries the origin marker of its source field.

### Usage rules

For each category, describe **how the project will use it**, following the
chosen convention. Keep it short and prescriptive. When the standards
JSON leaves the choice pending (`[pending]`), write the rule as `not
decided — see open_questions`.

### Version policy

State the runtime version the project targets, taken from
`stack.language_version`. If it is `[pending]`, say so.

### Official documentation links

Link only the technologies that appear in the table, and only to their
official documentation.
